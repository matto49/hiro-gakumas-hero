# 怎么贡献样本

谢谢！你只需要交截图，**不用标注**：正确文字由维护者那边的 AI 流程（Apple Vision + 两个不同来源的 LLM 看图 + 游戏词表，至少两家一致才定为正确文字）在合入时完成。

1. **攒 trace**：正常用 hiro-gakumas-hero 跑几局。建议开 `HIRO_TRACE_NATIVE=1`，会多存一份原生分辨率的截图（磁盘占用大，只在采集时开）。
   跑过的页面越多越好（选行动、商店、考试、各种弹窗……）。
2. **挑帧打包**（在主仓库里）：
   ```bash
   export HIRO_OCR_DATASET=<本仓库路径>
   python -m tools.ocr_dataset pick <trace 目录…> --contributor <你的名字> [--note <seq>=<这帧哪里认错了>]
   ```
   会按「平台 × 页面」挑得分散、去掉重复画面，打包到 `inbox/<你的名字>/<日期>/`。`--note` 可以多次给，标出你看到的认错。
3. **提 PR**：开个分支、提交 `inbox/` 下新增的目录。PR 描述里写：平台（DMM / MuMu / Mac …）、游戏窗口大小、设备、OCR 后端
   （trace 的 `run.json` 有 `platform` 的话已自动带进 `meta.json`）。
4. **维护者合入前**跑 AI 标注；有分歧的框维护者核对或标成不评测，你不用管。
5. **CI 会检查**：标注格式、图片和标注一一对应、sha256 对得上、帧 id 不重复。

## 不收

- 横屏 LIVE 演出帧、全黑 / 加载中的帧；
- 和已有帧内容完全相同的帧（自动去重）。

截图不需要遮挡（画面上只有用户等级这类信息，仓库是私有的）。
